**📰 Anthropic & OpenAI 速报 · 2026-06-07 Sunday**

🅰️ **Claude 产品更新详解**

本周 **Claude Code** 连续推送 v2.1.158 至 v2.1.168，重点增强了模型容错、Agent 可观测性、安全边界与设置管控。下文合并同主题功能展开。



**Claude Code：fallback 模型链与 glob 规则**
• 功能介绍：新增 fallbackModel 设置，最多配置三个备用模型，主模型过载或不可用时按序切换；同时在权限规则中支持 glob 模式（* 可拒绝所有工具调用），并强化了跨会话消息传递的安全性。
• 效果：在长时间 Agent 任务中，不再因为模型暂时不可用而中断，大幅提升可靠性；精细化的工具拒绝规则让企业管理员可以一次性锁定敏感操作，减少误配置风险。
• 使用限制：Claude Code v2.1.166 起可用；通过配置文件设置，全平台 CLI 环境生效。
[原文](https://github.com/anthropics/claude-code/releases/tag/v2.1.166)



**Claude Code Agent 交互改进：进度、阻塞与命令补全**
• 功能介绍：claude agents --json 新增 waitingFor 字段，显示 Agent 卡在什么权限提示上；并行工作展开时显示已完成／总数；/effort 确认选择会持久化为新会话默认值；点击斜杠命令自动填入提示而不立即执行。
• 效果：开发者在监控多个 Agent 任务时，能一眼定位“卡住”的原因；/effort 的持久化让相同偏好的连续工作流不再反复设置；命令补全免去记忆参数的负担。
• 使用限制：v2.1.161、v2.1.162 分批引入，CLI 全平台可用。
[原文](https://github.com/anthropics/claude-code/releases/tag/v2.1.161) [(v2.1.162)](https://github.com/anthropics/claude-code/releases/tag/v2.1.162)



**Claude Code 版本管控与插件列表**
• 功能介绍：新增 requiredMinimumVersion / requiredMaximumVersion 托管设置，版本不符时拒绝启动并指引用户升级；/plugin list 可列出已安装插件，并支持 --enabled/--disabled 过滤；/btw 回答旁出现 “c 复制” 快捷方式，保留原始 markdown 格式。
• 效果：企业管理员可强制开发团队使用指定版本，避免因版本差异导致的会话不一致；插件列表让用户快速审计当前环境；/btw 的复制功能方便分享完整答案。
• 使用限制：v2.1.163 起可用，托管设置需通过管理控制台下发。
[原文](https://github.com/anthropics/claude-code/releases/tag/v2.1.163)



**Claude Code 安全加固：启动文件与构建配置写入提示**
• 功能介绍：写入 shell 启动文件（.zshenv, .bash_login 等）或 ~/.config/git/ 前增加二次确认；acceptEdits 模式下写入会执行代码的构建配置文件（.npmrc, .yarnrc*, bunfig.toml 等）也需提示；单文件 grep/egrep/fgrep 读取后不再要求额外 Read 操作。
• 效果：防止 Agent 在自动模式下向敏感启动文件注入恶意命令；减少对构建工具配置的非必要写操作；grep 后自动引用文件降低上下文消耗。
• 使用限制：v2.1.160 起有效，CLI 全平台；acceptEdits 提示为默认开启。
[原文](https://github.com/anthropics/claude-code/releases/tag/v2.1.160)



**Claude Code 多平台 Auto Mode 扩展**
• 功能介绍：Auto Mode 现在支持 Bedrock、Vertex 和 Foundry 上的 Opus 4.7 与 Opus 4.8，通过 CLAUDE_CODE_ENABLE_AUTO_MODE=1 开启。
• 效果：使用云平台模型的企业用户也能体验自动化编码，无需手动审批每一步操作，提升大型重构任务的效率。
• 使用限制：v2.1.158 起可用；仅限 Opus 4.7/4.8 模型，需在云平台部署时设置环境变量。
[原文](https://github.com/anthropics/claude-code/releases/tag/v2.1.158)

🅾️ **OpenAI 产品更新详解**



**ChatGPT 全新记忆系统 “Dreaming”**
• 功能介绍：ChatGPT 引入全新记忆机制，能跨会话持续记住用户偏好与上下文，并随时间推移自动保持信息的新鲜度与相关性。
• 效果：不再需要每次对话都重复背景设定，ChatGPT 会像长期助手一样了解用户的工作习惯与兴趣，回答更个性化；与旧版记忆相比，新系统能主动淘汰过时信息，避免“越记越错”。
• 使用限制：(推测) 将逐步推送至 ChatGPT Free/Pro/Team/Enterprise，[原文](https://openai.com/index/chatgpt-memory-dreaming) 提到“今天上线”，具体档位与平台需等后续通知。
[原文](https://openai.com/index/chatgpt-memory-dreaming)



**GPT-Rosalind 新增生物学推理与实验工作流能力**
• 功能介绍：专为生命科学打造的 GPT-Rosalind 获得增强：更强的生物学推理、药物化学专业知识、基因组分析以及实验工作流支持。
• 效果：研究人员可以用它设计基因敲除实验、预测化合物活性、解析基因组变异，并将这些步骤串成可复现的工作流，加速药物发现与精准医疗。
• 使用限制：Rosalind 系列目前对通过审核的开发者及美国政府合作伙伴开放（Rosalind Biodefense 项目），常规 ChatGPT 用户不可直接使用。
[原文](https://openai.com/index/introducing-new-capabilities-to-gpt-rosalind)



**Codex 扩展：面向所有人的插件、站点与注释**
• 功能介绍：发布新一批 Codex 插件、网站和注释功能，覆盖分析师、市场人员、设计师、投资人等多种角色，使其无需编码即可用 AI 完成数据分析、自动化与内容创作。
• 效果：一个营销人员可以直接在内部文档中通过 Codex 提取销售趋势并生成图表；设计师可以用插件快速生成组件变体。相比早前主要面向开发者的定位，这次更新真正把 Codex 变成了通用生产力层。
• 使用限制：ChatGPT Enterprise / Teams 环境内可用，推测需管理员启用相关插件。
[原文](https://openai.com/index/codex-for-every-role-tool-workflow)



**OpenAI 前沿模型与 Codex 正式上线 AWS**
• 功能介绍：OpenAI 前沿模型（含 GPT 系列）及 Codex 在 AWS 上全面可用，企业可直接通过现有 AWS 环境、控制面板与采购流程使用。
• 效果：已在 AWS 上运行业务的公司现在可以无缝接入 OpenAI 能力，无需另外签约或解决网络合规问题，极大缩短从评估到上线的时间。
• 使用限制：通过 AWS Marketplace 提供，适用 AWS 商业条款；具体模型列表未详列，但包含 “frontier models” 及 Codex。
[原文](https://openai.com/index/openai-frontier-models-and-codex-are-now-available-on-aws)
